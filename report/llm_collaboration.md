# 大模型协作记录

## 1. 概况

| 项目 | 内容 |
|---|---|
| 模型 / 工具 | Claude（claude.ai，Opus 系列模型，带代码执行与文件处理环境） |
| 协作时间 | 2026 年 10 月下旬至 11 月初（作品提交前的完善阶段） |
| 协作环节 | 技术文档撰写与审校、示波器与 ILA 实测数据分析、定点 PID 复算、报告与海报图表、演示视频与 PPT、开源仓库整理 |
| 人工职责 | 提供实测数据、工程文件与实验照片；确认物理事实与数据口径；对每一处结论性修改做最终取舍 |

说明：本文中的"任务"为每次协作的任务描述，经整理后保留原意；"模型回答"为摘要；所有修改均可在仓库的报告、数据或脚本中找到对应证据。

## 2. 协作流程

```
提出任务 → 模型起草 / 分析
        → 模型对照原始数据（ILA CSV、示波器 CSV、综合报告、RTL）自查
        → 发现疑点：列出依据并向人提问，不自行假设
        → 人确认事实与口径 → 模型修改
        → 用脚本复算、渲染文档或回归测试验证
        → 可复用的经验写入 skill/
```

这一流程的核心是：**模型负责起草、核对和提出疑问，事实与口径由人确认**。下面的案例中，有多处是模型主动停下来提问，而不是直接改写结论。

## 3. 典型案例

### 案例 1：失锁恢复时序表述的纠正

- **任务**：对全文技术表述与实测数据做一致性审查。
- **模型回答**：通读后指出，第 1.3 节与第 3.3.6 节写的"120 ns 内重新开始扫描和 kick"与 ILA 记录不符：第 4135 点重新进入扫描，而 kick 要等扫描到达触发电压后才执行，两者相隔约 8.25 ms。
- **纠正**：两处改为"120 ns 内重新开始扫描，随后重新执行 kick"。
- **验证**：对照 ILA 事件表（报告表 3-5）与示波器重扫记录（图 3-9），一致。
- **经验**：概括性语句容易把相隔很远的多个事件合并成一个时间点，时间类结论必须回到原始记录逐点核对 → `skill/pitfalls.md` E5。

### 案例 2：用 ILA 实测数据复算 Q8 定点 PID

- **任务**：用控制域 ILA 一帧数据，按 RTL 中的定点公式复算 PID 修正量，与 FPGA 实际输出逐次比较，为报告提供"PID 运算正确"的板上证据。
- **模型回答**：编写 `verify_pid_from_ila.py`，按 RTL 位宽、算术右移 8 位、积分与输出饱和规则复算；考虑到输出寄存器晚 1 拍，取下一行的修正量比较。
- **问题与处理**：第 3 次更新发生在 PID 撤销的前一拍，单看修正量会判为不一致。脚本同时检查下一拍的使能信号，将其标注为"已撤销、未输出"，与设计行为一致。
- **验证**：3 次更新中前 2 次复算值 29、162 与 ILA 完全一致，第 3 次 588 未输出，输出 `RESULT=PASS`，对应报告表 3-6。
- **经验**：→ `skill/fixed_point_golden_check/`。

### 案例 3：实测数据的口径一致性

- **任务**：提交前检查摘要、正文和指标表中"台阶保持时间"的写法是否一致。
- **模型回答**：指出文档中有"保持至示波器记录结束（≥24h）""受记录长度限制"等写法，而图 3-8(c) 的示波器记录横轴只有约 9.4 ms，图 3-9 整段记录约 20 ms，同一句话中的记录方式与时长不能同时成立；另外"提高十一个数量级"按 24 h ÷ 3.2 μs ≈ 2.7×10¹⁰ 计算应为约十个数量级。模型列出全部位置后请人确认 24 h 数据的来源。
- **纠正**：经人确认 24 h 来自长期运行测试，与示波器记录分开表述：删去"示波器记录结束""受记录长度限制"等矛盾字样，示波器图只用于说明微秒到毫秒尺度的过程；数量级改为"约十个"。
- **经验**：同一指标可能来自不同测试，必须写清每个数字的测试口径 → `skill/pitfalls.md` E4。

### 案例 4：无原始数据支撑的统计数值

- **任务**：根据新到的实测数据完善报告第三部分。
- **模型回答**：发现早期草稿中有激发成功率、平均激发时间等统计数值，但提供的数据中只有单次示波器记录和一帧 ILA，没有对应的多次统计记录；同时控制逻辑本身不统计尝试次数。模型建议删除这些数值，改为如实说明"控制逻辑不统计尝试次数，统计测试是下一步工作"，并在 4.1 节列出需要增加的 RTL 计数器。
- **处理**：人确认后采纳。
- **经验**：报告中的每个数值都应能追溯到一份原始记录。

### 案例 5：参数与照片信息不自行猜测

- **任务**：用 VIO 截图和实验平台照片补充报告第 3.2 节与海报。
- **模型回答**：
  - VIO 截图中的参数（Kp、Kd、确认次数、触发电压等）与表 3-4 的 ILA 测试条件不同，模型先询问截图用途，而不是把截图参数写成测试条件。人确认"只是界面截图"后，图注写明"某次实验的参数快照，与表 3-4 测试条件不同"。
  - 照片中有两个光电探测器，模型询问哪一个对应 PD1（透射）和 PD2（频梳功率）；人回答"不确定"，因此图上只标型号，不标 PD 编号。
- **经验**：照片和截图的标注只写能确认的信息。

### 案例 6：示波器数据解读的保守处理

- **任务**：分析三种条件（无 kick / kick 无 PID / kick + PID）的示波器记录，测量台阶持续时间并作图。
- **模型回答**：测得台阶约 0.5 μs、约 3.2 μs，以及 PID 伺服下台阶持续保持。分析中注意到一组记录里 CH1（AOM）下降比 CH4（频梳功率）早约 0.2 μs，但这与通道、探头延迟差在同一量级，不足以说明因果先后，因此报告中没有写出先后关系。
- **经验**：→ `skill/pitfalls.md` D6、`skill/scope_csv_tools/`。

### 案例 7：文档格式与工具链问题

- **任务**：修改报告格式并准备提交文件。
- **模型回答与处理**：
  - 正文引用了参考文献 [18]，但文献列表中没有该条，模型指出后由人决定处理方式。
  - Si₃N₄、1.6×10⁶ 使用 Unicode 上下标字符，在 WPS 中出现空隙，改为普通数字加上下标格式（7 处）。
  - 批量修改图号与数值时，部分文字被 Word 拆在多个文本段中，按段落拼接定位后再修改，避免遗漏。
  - 非 Word 工具转换 PDF 时公式显示为空白，因此提醒用 Word/WPS 导出最终 PDF。
- **经验**：→ `skill/pitfalls.md` E1～E3。

## 4. 分工总结

| 环节 | 大模型完成 | 人完成 |
|---|---|---|
| 数据 | 解析 CSV、测量台阶、按 RTL 公式复算、作图 | 采集原始数据，说明每份数据的测试条件 |
| 文档 | 起草与改写、全文一致性审查、格式修改 | 确认物理事实与数据口径，决定取舍 |
| 交付物 | 海报、PPT、视频剪辑与字幕、仓库整理与 README | 提供照片与录像，审阅视觉效果 |
| 结论 | 列出疑点与依据 | 最终判断结论是否成立 |

**体会**：

1. 大模型在批量数据处理、文档一致性检查和格式化工作上效率很高，但它可能把多个事件概括成一句话、把不同测试的数值混用，所以所有时间和数值结论都要有原始数据对照。
2. 最有价值的协作方式是让模型"列出疑问并给出依据"，由人确认后再修改；本记录中案例 3、4、5 都是这样处理的。
3. 协作中反复出现的检查项已整理为 `skill/llm_prompt_workflows/` 中的任务模板和 `skill/pitfalls.md`，可供其他队伍直接使用。
