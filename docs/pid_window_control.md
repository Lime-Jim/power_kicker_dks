# 可选PD入窗门控与失锁策略（2026-09-21）

本次基于已经加入独立PID启动延时的 `D:/power-kicking_handoff_20260907/code/vio_stable`。新增一个1位VIO输出及失锁重新捕获流程：扫描→kick→PID捕获/保持→失锁→清除PID状态→重新扫描。PID增益和核心计算公式保持不变。

## 入窗参数可通过VIO调整

| PID VIO输出 | 参数 | 含义 | 现有保存值 |
|---|---|---|---:|
| probe_out1 | vio_pid_target_mV | 校正后PD的目标值/窗口中心，mV | 133 |
| probe_out2 | vio_pid_window_mV | 窗口半宽，mV；上下边界均包含 | 10 |
| probe_out7 | vio_pid_confirm_samples | 连续入窗有效采样数，1～255；0按1处理 | 3 |
| probe_out10 | vio_pid_require_window | 是否需要PD窗口门控，0或1 | 新增，默认1 |

因此现有保存配置要求校正后PD连续3个有效采样在123～143 mV内。代码先减去固定21 mV偏置，再用于窗口及PID误差计算。probe_out7的既有IP位宽为16、RTL仅使用低8位，不能将大于255的值当作更长的确认次数。保存值来自文件，本次未读取板上实时值。

## 新开关

- `vio_pid_require_window=1`：连续入窗才启用PID。进入后任一有效采样出窗便退出，随后自动从扫描起点重新开始完整序列。
- `vio_pid_require_window=0`：不要求入窗，满足反馈开启、kick延时到达、正向扫描停止后即可进入PID。首次连续入窗确认之前允许在窗口外纠偏；首次确认入窗后开始监测失锁，后续出窗同样触发重新扫描。这一区分避免刚在窗口外启用PID就立即触发重扫。
- 默认值及旧保存文件兼容值均为1。旧保存文件不会被改写；以后调用参数保存工具会保存该字段。
- 新开关实时生效，独立启动延时仍是每轮锁存。0→1时立即恢复当前窗口资格约束，可能暂时退出PID；1→0时其他门控满足即可启用PID。一旦本轮已完成PID运行中的连续入窗确认，关闭入窗要求也不会关闭本轮失锁监测。
- 硬件/按钮复位和`vio_pid_clear=1`在绕过模式下仍能禁止PID并清除修正；清除解除后如果其他条件仍成立，绕过模式会重新启用。
- 窗口检测器始终根据真实PD工作，绕过模式不会伪造step_found。此时`w_pid_active=1`且`w_pd_step_found=0`是合法状态。

新参数使用 `u_vio_pid/probe_out10`，IP和顶层均为1位，初值1。原PID输出0～9保持原顺序，特别是probe_out9仍为32位独立启动延时。其他既有输出保持不变。

## 失锁判定

新增恢复控制在PID实际运行并连续入窗后记录本轮已捕获。随后任一有效采样满足 `abs(PD_corrected - target) > window`，窗口检测器撤销step_found，恢复控制产生重新扫描请求。这仍是幅值窗口判据，并非物理光学锁定的直接证明；尚未增加连续多次出窗确认、退出滞回或采样超时判据。

需要窗口时，单次出窗首先撤销PID使能；不要求窗口时，完成首次入窗确认后也会因出窗产生恢复请求。请求一旦产生便禁止原位置重入，在随后的控制时钟启动新序列。目标或窗口的实时修改也可能导致下一次采样出窗。没有新的有效采样时，窗口判定保持原状态；采样中断尚不能自动识别为失锁。

绕过模式首次捕获前，step_found可以一直为0，此时不因尚未入窗而重扫；目前也没有捕获超时。超出修正限幅只使输出饱和，本身不触发失锁重扫。反馈关闭、手动clear、按钮/失钟复位会清除本轮捕获标记，不被当作失锁自动重试。

## 失锁后的恢复循环

1. 禁止本轮PID继续作用或在原位置重新启用，产生一次内部重新扫描请求。
2. 控制器将NKT基准设为扫描起点、AOM设为kick前基准，锁存新一轮VIO波形和延时配置，进入S_SCAN。恢复请求不受手动启动按钮20 ms锁定限制，也不要求打开自动扫描开关。
3. 新序列开始时统一清除PID积分、前次误差、实时/冻结修正、窗口确认和本轮捕获标记；kick及PID延时状态重新计数。
4. 完整执行扫描、kick和独立PID启动延时，再按require_window选择是否需要入窗确认，随后进入PID。
5. 后续再次失锁会重复同一循环，不限一次重试。正常PID运行时抑制周期性自动回扫/下一轮启动，避免原自动频率打断闭环。尚未进入PID的自动扫描仍按原频率尝试；回扫期间不允许PID接管移动中的基准值。

手动把反馈总开关关闭是另一条路径：现有代码会冻结最后有效NKT修正；手动`pid_clear`或新一轮扫描开始会清除。`vio_pid_locked`仍表示修正有效或冻结有效，不能作为真实光学锁定的证据，在绕过模式下尤其如此。

本次通过每次新扫描清除PID状态，解决失锁重试路径保留旧积分/修正的问题；同一轮手动关闭再开启反馈的旧冻结语义仍保留。积分抗饱和不足、修正限幅低15位和既有探针位宽等限制仍见前次`PID_DELAY_REVIEW.md`。
