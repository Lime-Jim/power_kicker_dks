## 新参数

`u_vio_pid/probe_out9` → `vio_pid_start_delay_ns`，无符号32位，单位ns，默认200。从内部kick上升沿计时，0立即到期，其余向上量化到40 ns。例如200→200 ns，210→240 ns。最大输入4294967295→107374183拍，4294967320 ns；换算先扩展位宽，避免最大值加39溢出。

延时在扫描序列开始时锁存，修改要到下一轮生效。计时从实际kick事件开始，跨过下降、回升及DONE状态继续；新一轮或复位清除计时。无kick时不会误启用。`vio_kick_fall_ns`只控制下降波形，已从PID资格判断中移除。

这里的复位指控制器硬件复位/按钮复位。`vio_pid_clear`仍只清除PID状态和窗口确认，不重启kick计时；反馈开关也不改变本轮已锁存的计时起点。

PID使能条件为：反馈开关打开 ∧ 延时到达 ∧ 正向扫描停止 ∧ PD连续N个有效采样进入目标窗口。它是最早允许检测的时刻，不是首次修正量输出的保证时刻。窗口检测从门控开放后的采样开始，PID首次更新再等一个有效采样节拍，DAC传输也有延迟。

旧保存文件缺少新字段时，恢复工具使用固定200 ns；不再跟随下降时间。新的保存操作会记录该字段。现有probe_out0～8顺序保持不变，IP已有的其他输出端口保持不变。

## 当前PID设置

以下来自 `last_vio_parameters_v2.tcl`，不是实时读取硬件：

| 参数 | 保存值 | 源码语义 |
|---|---:|---|
| feedback_enable | 0 | 关闭反馈，因此当前保存设置本身不会自动进入PID |
| target_mV | 133 | 与减去固定21 mV偏置后的PD值比较 |
| window_mV | 10 | 目标±10 mV，含边界 |
| confirm_samples | 3 | 连续3个有效反馈采样入窗；0按1处理 |
| Kp | 256 | Q8，1.0 DAC码/ADC码 |
| Ki | 8 | Q8，每次有效采样累加0.03125×误差码 |
| Kd | 0 | 未使用微分项 |
| corr_limit | 1000 | ±1000 DAC码，按代码1500 mV满量程约±45.8 mV |

目标133 mV对应校正后123～143 mV的窗口；按固定21 mV校正，原始ADC换算值约144～164 mV可进入此窗口（中心约154 mV，存在整数换算误差）。如果实验人员把133 mV理解为校正前读数，会出现预期入窗但程序不入窗的情况。

ADC代码配置为每128点取一个样本，不做平均；250 MHz ADC条件下约512 ns一个反馈样本。Ki是每采样步增益，代码没有单独乘入采样时间；采样周期改变会改变实际积分速度。Kp=256是码值域比例1，并不表示物理mV/mV比例1。

正Kp/Ki要求正的局部对象增益：NKT DAC增加时PD应增加，才与 `error=target-measured` 构成负反馈。源码不能确定当前光路工作点的斜率、动态延迟和稳定裕量，因此不能仅凭上述数值判定增益合适。

## 已证实的问题与行为

1. **出窗即退出。** `pd_pid_feedback.v` 在任意一个有效采样离开窗口时清零step_found，pid_active随之撤销，最终NKT恢复基准值。没有闭环状态锁存、退出滞回或失锁确认。扰动较大时会停止纠偏并反复切换。新增延时不改变这一行为。
2. **重新进入会使用旧状态。** PID的积分、前次误差和correction只在reset/clear清除；失去enable时保持。`nkt_correction_valid`根据loop_active而非“新修正计算完成”置位，因此入窗后、下一次采样计算前，旧修正可能重新作用于DAC。单元仿真已复现。
3. **积分抗饱和不足。** 积分累加器有固定上下限，但未随输出限幅冻结或回算；输出已经达到±corr_limit后仍会继续累积。仿真显示误差回到0后仍可能保留饱和输出。应评估条件积分或回算抗饱和。
4. **自动扫描不会因PID启动而取消。** 保存设置启用50 Hz自动扫描；控制器的自动回扫/下一轮逻辑没有使用pid_active作为抑制条件。它适合反复试验，不能视为已实现“一旦锁定便停止扫描、持续保持”。启动延时大于自动周期时每轮会重新计时，可能始终无法进入PID。
5. **关闭反馈保留修正。** 现有实现会冻结最后有效NKT修正；关闭开关不等于DAC回到基准，清除需要pid_clear。feedback_locked包括冻结有效，并不证明实际闭环稳定。
6. **限幅参数范围。** 核心取corr_limit的低15位，当前1000合法。写入32768～65535会按低15位处理而不是饱和到32767；在修正此行为前，有效使用范围为0～32767。
7. **既有VIO位宽不完全匹配。** IP里的clear（probe_out6）和confirm_samples（probe_out7）都为16位，RTL分别只用1位和8位。当前保存的0和3不受影响，但写入超出范围的值会截断；例如确认次数256会变成0，再按1次处理。本次保留旧探针布局，新延时的32位在IP、顶层与控制器中一致。

建议在持续锁定实验之前，单独确定进入后保持/失锁退出策略、重入时积分和修正量如何衔接，以及自动扫描何时停止。本次只实现已确认的独立延时，不擅自改动这些闭环行为或实验增益。
