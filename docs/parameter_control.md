# 当前参数控制约定（VIO 主用，UART 备用）

当前 bitstream 的踢动、扫描与 PID 参数仅来自 `u_vio_control` 和 `u_vio_pid`。UART 接收和应答代码保留在独立的 `uart_power_kick_params.v`，没有连接到实际控制参数，也没有自动切换源的逻辑。

## VIO 操作

使用与本次 bitstream 配套的 LTX。`open_vio_with_last_parameters.tcl` 提供参数恢复、保存和下载工具；在 Hardware Manager 中调用会访问已连接硬件。本次构建和回归没有执行下载，也没有改写 `last_vio_parameters*.tcl` 的实验数值。

控制 VIO 输出顺序：

| 输出 | 名称 | 单位 |
|---|---|---|
| 0 | auto_sweep_enable | 0/1 |
| 1 | auto_sweep_freq_Hz | Hz，0沿用100 Hz默认值 |
| 2 / 3 | kick_final_mV / kick_min_mV | mV |
| 4 / 5 | kick_fall_ns / kick_rise_ns | ns，实际向上量化到40 ns周期 |
| 6 / 7 / 8 | sweep_start_mV / sweep_final_mV / sweep_trigger_mV | mV |
| 9 | sweep_scan_us | µs，顶层0沿用100000 µs默认值 |
| 10 | kick_base_mV | mV，kick前基准 |
| 11 | sweep_stop_offset_ns | 有符号ns，相对kick开始的扫描停止偏移 |

PID VIO 输出顺序：使能、目标mV、窗口mV、Ki、Kd、Kp、clear、连续确认次数、DAC码修正限幅、`vio_pid_start_delay_ns`（probe_out9）、`vio_pid_require_window`（probe_out10）。目标与三个增益为有符号16位；Kp/Ki/Kd使用Q8，例如256=1.0。`force_enable` 和 `hold` 没有独立VIO探针。

`vio_pid_start_delay_ns` 是无符号32位纳秒数，范围0～4294967295，默认200。以FPGA内部kick上升沿为起点，向上量化到40 ns；0表示从kick开始即允许后续资格判断。延时与波形参数在每轮序列开始时一起锁存，途中修改在下一轮生效。延时到达后仍要求反馈使能、正向扫描已停止；校正后的PD连续入窗条件由`vio_pid_require_window`控制。实际首次PID修正需等待有效反馈采样节拍，启用入窗条件时还需等待窗口确认。此参数不等于保证在该纳秒时刻已经输出PID修正。

`vio_pid_require_window`是1位开关，默认1。1要求连续入窗才启用PID；0允许在窗口外启用PID，首次连续入窗前持续纠偏。两种模式在本轮PID运行并确认入窗后，都监测单次有效采样出窗并触发失锁重扫。反馈总开关、kick延时、扫描停止、控制器复位及pid_clear仍有效。模式实时生效：从0切回1时，如果当前PD未确认入窗，会暂时退出PID；由1改为0时，其他条件满足即可启用PID。窗口检测在两种模式中都继续运行，`w_pd_step_found`报告实际入窗确认，绕过捕获期间允许其为0而`w_pid_active`为1。

窗口可用`vio_pid_target_mV`（中心）、`vio_pid_window_mV`（半宽）和`vio_pid_confirm_samples`（连续有效采样数）实时调整。新增失锁恢复流程为：退出PID→清除积分/修正/确认状态→回到扫描起点→重新扫描→kick→重新等待PID延时及所选入窗条件。恢复不要求打开自动扫描；PID正常运行时抑制周期性回扫，未捕获时的自动扫描保留。完整说明见`PID_WINDOW_CONTROL.md`。

`vio_kick_fall_ns` 只控制AOM下降段。PID延时不再读取`kick_fall_done`，因此可以早于或晚于下降完成。延时跨越kick结束继续计数，每轮重新启动或复位时清零；没有kick事件就不会启动PID计时。自动周期短于延时时，每轮都会重新计时，不会累积到下一轮。

旧参数保存文件没有新字段时，恢复工具给PID延时设置独立的200 ns默认值，之后保存会包含新字段；已有实验参数文件未改写。需要重新构建并使用配套BIT/LTX才能看到新探针。PID逻辑与当前参数的审查见`PID_DELAY_REVIEW.md`。

状态机在空闲时随时钟更新起点和AOM基准，启动或按钮复位时锁存波形配置；扫描/踢动进行中修改波形参数，要到下一次启动/复位才生效。新增PID启动延时也按轮锁存；自动使能、自动频率与其他PID参数仍采用现有实时生效语义。一次试验前应先停止自动扫描、关闭PID并清除修正，提交整组参数后再启动，避免跨多个VIO提交形成过渡配置。

当前保存的连续确认次数仍为3，本次没有替用户改成1。需要快速反馈时可明确执行 `set_fast_feedback_v1_vio_params.tcl`，确认效果后再保存。ADC是每128点取一个原始样本（512 ns），没有128点平均。ADC到逻辑域的跨域等待实测数字仿真为280–320 ns；首次PID修正还包含窗口确认、下一个反馈节拍和DAC传输，因此不能只用文件夹的“1us”名称推断整条闭环延迟。

手动关闭PID后保留最后有效NKT修正是现有行为；`pid_clear`或新一轮扫描会清除。失锁重试一定启动新扫描并清除旧PID状态。AOM不叠加PID。`feedback_locked`表示修正有效/冻结有效，不是闭环稳定性判定。

## UART 兼容边界

串口为115200、8N1。请求是6字节：`A5 地址 D3 D2 D1 D0`，32位载荷高字节先发。应答为1字节地址回显。部分寄存器只取载荷低16位。

| 地址 | 保留字段 |
|---|---|
| 00 / 01 / 02 | DAC1起点码 / 触发码 / 扫描旧版ms字段 |
| 03 / 04 / 05 / 06 | DAC2基准码 / 最小码 / 下降旧版ms字段 / 上升旧版ms字段 |
| 10 / 11 / 12 | PID使能 / 目标ADC码 / 窗口ADC码 |
| 13 / 14 / 15 / 16 | Kp / Ki / Kd / DAC码修正限幅 |

应答只确认协议处理，不能解释为“已更新VIO或模拟输出”。现阶段无UART读回；未被实际控制逻辑使用的备用寄存器可能被综合优化掉。未知地址保持原有空操作/回显行为，没有校验和和帧超时恢复；上位机应等待应答后再发下一帧。

以后接入UART时需要明确版本化协议、单位换算、整组参数原子提交、源选择规则以及状态/错误读回，不能直接把旧版ms字段接到当前us/ns端口。

## 复位边界

控制状态机硬件复位输出固定为0，配置在正常时钟沿装载。逻辑启动计数器在MMCM失锁时重置；ADC采样域、25 MHz逻辑域各自使用异步置位、同步释放的复位同步器。

这不等于物理DAC在任何失钟条件下都立即归零：现有DAC发送模块仍使用本地上电计数器，500 MHz接收寄存器没有顶层外部清零端口。如果25 MHz时钟停止，DAC可能保持上一值。板级安全停机/失钟联锁需要单独设计和硬件验证，本次数字回归只证明正常时钟下的传输与控制行为。
