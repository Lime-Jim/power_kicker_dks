# toggle_cdc — 多位数据跨时钟域：保持寄存器 + toggle 同步

## 适用场景
源时钟域每隔若干周期产生一个多位数据（如 ADC 抽取后的样本、控制域给 DAC 的码值），需要送到另一个连续运行的时钟域，并且每个数据在目标域只被使用一次。

## 结构
1. 源域：把新数据写入**保持寄存器**，同时翻转 1 位 `toggle`。保持寄存器在下一次更新前不变。
2. 目标域：只对 `toggle` 做 3 级同步（`ASYNC_REG = "TRUE"`）；检测到同步后的 `toggle` 变化时，**再等待 N 拍**（本项目 N = 4）后装载保持寄存器，并产生一个单周期 `sample_tick`。
3. 后级所有计数、积分只在 `sample_tick` 时更新。

参考实现：
- ADC 250 MHz → 控制 25 MHz：`../../src/power-kicker-fast-feedback-v1.srcs/sources_1/new/pd_adc_capture.v` 第 21–70 行
- 控制 25 MHz → DAC 500 MHz：同目录 `test_ad9122.v` 中 `data_req_sync` 部分

## 使用前必须算的两个数
设目标时钟周期为 `Td`，同步级数为 `S`，等待拍数为 `N`，源数据最短保持时间为 `Th`：

```
装载延迟  T_load ≈ (S + N + 1) × Td     （本项目 ADC 方向：7～8 × 40 ns = 280～320 ns）
条件      T_load < Th                   （本项目 ADC 方向：Th = 128 × 4 ns = 512 ns）
```

不满足时，下一笔源数据可能在目标域装载前覆盖保持寄存器。检查清单见 `checklist.md`。

## 为什么不用单周期脉冲
源域 250 MHz 下单周期脉冲只有 4 ns，比 25 MHz 目标时钟周期（40 ns）短得多，可能被漏采；toggle 的电平变化会一直保持到下次更新。

## 失效条件
- 没有握手应答：源域更新间隔小于装载延迟、或目标时钟可能停顿时，不能使用，应改用带握手的结构或异步 FIFO。
- 仿真不能验证亚稳态概率和物理走线偏斜；正式签核时需为保持数据总线补充最大延迟约束（注意全局异步时钟组的优先级会屏蔽这类约束）。

## 已验证的效果
`tb_adc_capture_regression` 12463 项、`tb_dac_regression` 53092 项检查通过；Vivado CDC 报告将两条通路识别为"同步 toggle（CDC-3）+ 多位保持数据（CDC-15）"。ILA 实测一帧内 640 个有效样本间隔为 12 或 13 个控制周期，平均 511.99 ns，无丢样、无重复。

## 来源
多位 ADC 样本若直接打拍同步，目标时钟恰好采到正在变化的总线时会得到新旧位混杂的错误码；另外 PID 最初每个 40 ns 控制周期都积分，同一个 512 ns 样本被累加十几次。两处都改为"每个样本只产生一次 tick"后，PID 输出才与公式一致。
