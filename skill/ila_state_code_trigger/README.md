# ila_state_code_trigger — 状态码观测与 ILA 触发

## 适用场景
实时控制系统的关键事件只持续几十到几百个时钟周期（如"孤子台阶确认 → PID 接管"），ILA 用普通信号触发很难稳定抓到，或者抓到了也难以判断系统处在哪个阶段。

## 方法
1. 新增一个**只读**的状态归纳模块（本项目为 `capture_phase_status.v`），输入底层状态机状态、kick、PID 使能等信号，输出 2～3 位的阶段码，例如：

   | 码 | 阶段 |
   |---|---|
   | 0 | IDLE |
   | 1 | SCAN（扫描、回扫、失锁重扫） |
   | 2 | CAPTURE（kick 后等待确认） |
   | 3 | PID_FEEDBACK（已确认并闭环） |

2. 另加一个"历史标志"（曾经进入过状态 3 后保持为 1），接到 VIO 输入，防止 VIO 刷新太慢漏看短暂的成功。
3. 控制域 ILA 以阶段码等于 3 作为触发条件，触发位置放在缓存中部，一帧即可同时看到触发前的扫描、kick 和触发后的闭环、失锁、重扫。
4. 抓取与导出：`../../src/capture_ila_tools.tcl` 提供 `pk_capture_now [csv路径]`。

## 失效条件
- 状态码模块是寄存器输出，比被观察事件晚 1 个控制周期（本项目为 40 ns）。精确判断先后顺序时要同时看底层信号。
- 状态码只是对程序判据的归纳，不是额外的物理检测：本项目中"状态 3"只说明功率落入目标窗口，不能区分单孤子与多孤子。
- ILA 显示名可能被加 `_1` 后缀（同一信号同时接 VIO 和 ILA 时），应按探针编号对应。

## 已验证的效果
本项目一帧 8192 点 ILA 完整记录了 SCAN → CAPTURE → PID → 出窗 → 重扫，报告表 3-5 的全部事件时间均取自这一帧，数据见 `../../data/ila/`。

## 来源
仅用 kick 等底层信号触发时，PID 是否接管、何时失锁需要逐点人工判断多个信号的组合；加入状态码后，每次触发都能直接落在"进入 PID"的时刻，并据此调整目标值、窗口与增益。
