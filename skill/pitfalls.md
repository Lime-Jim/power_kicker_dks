# 踩坑清单

按"触发条件 → 现象 → 排查与解决"整理。标注"已修复"的条目在本项目中已经处理，仍列出供其他工程参考。

## A. Vivado 工程与约束

| # | 触发条件 | 现象 | 排查与解决 |
|---|---|---|---|
| A1 | 在已有工程目录中执行 `create_project -force` 重建工程 | 同名 `.srcs` 目录被删除，源码丢失 | 只替换 XPR 并先备份，见 `vivado_portable_project/` |
| A2 | 多次在 GUI 中保存工程、增删 IP | XPR 中残留旧 IP、生成文件（`.gen`、`synth/*.v`）或 `../` 路径，换电脑无法打开 | 构建前用清单脚本检查所有文件引用为 `$PSRCDIR/` 或 `$PPRDIR/` |
| A3 | 在普通 XDC 中写 `source xxx.tcl` | 托管 XDC 解释器不执行该命令，约束没有生效，也不一定报错 | 改用 `FILE_TYPE=Tcl`、仅实现阶段、`PROCESSING_ORDER=LATE` 的约束文件 |
| A4 | Tcl 约束中用 `info script` 定位同目录文件 | 实现子进程中返回 `.runs/impl_1/` 下的临时路径，找不到参数文件 | 用 `get_files` 取约束文件的注册路径 |
| A5 | 外部 IO 约束模板中参数留空 | 空值被当作 0 ns，时序报告显示通过 | 缺参时明确输出 PROVISIONAL，`--signoff` 下直接失败，见 `external_io_timing_gate/` |
| A6 | 只看 DRC 0 错误或内部 WNS 为正 | 误以为 CDC 与外部接口均已收敛 | 分别查看 CDC 报告（CDC-7 等 Critical）与外部 IO 状态，报告中分开陈述 |
| A7 | 全局 `set_clock_groups -asynchronous` 后再给跨域总线加最大延迟约束 | 新约束被异步时钟组屏蔽 | 处理约束优先级，或改用 `set_max_delay -datapath_only` 并排除在时钟组之外 |

## B. 跨时钟域与复位

| # | 触发条件 | 现象 | 排查与解决 |
|---|---|---|---|
| B1 | 多位数据（ADC 样本）直接打拍同步到另一时钟域 | 采到新旧位混杂的错误码 | 保持寄存器 + 1 位 toggle 同步 + 延迟装载，见 `toggle_cdc/` |
| B2 | 快时钟域单周期脉冲送到慢时钟域 | 4 ns 脉冲被 40 ns 时钟漏采 | 改用 toggle 电平变化 |
| B3 | 慢样本（512 ns）驱动快时钟（40 ns）中的积分或计数 | 同一样本被累加十几次，PID 输出与公式不符 | 只在 `sample_tick` 时更新；本项目已修复 |
| B4 | 调试按键消抖器复位来自另一时钟域 | CDC 报告出现 CDC-7 Critical | 复位在目标时钟域内同步释放；本项目该路径只连到 ILA，已在文档中说明 |
| B5 | 复位直接用组合逻辑驱动（如 UART） | 方法学报告 LUTAR 警告 | 复位先寄存再使用；本项目已修复 |

## C. 控制算法（本项目 PID 闭环）

| # | 触发条件 | 现象 | 排查与解决 |
|---|---|---|---|
| C1 | 失锁后重新进入 PID 时不清除积分与修正量 | 旧修正量立即作用到 DAC，重新激发失败 | 失锁重扫请求同时作为 PID 清零信号；本项目已修复 |
| C2 | 积分限幅固定、不随输出限幅冻结 | 输出饱和后积分继续累积，误差回零后仍保持饱和输出 | 采用条件积分或回算抗饱和（本项目中仍为已知限制） |
| C3 | 自动周期扫描不受 PID 状态抑制 | PID 刚接管就被下一轮扫描打断 | PID 工作期间屏蔽自动启动，只允许失锁重扫请求启动；本项目已修复 |
| C4 | VIO 探针位宽与 RTL 使用位宽不一致（16 位探针、RTL 只用低 8 位） | 写入超范围值被截断，例如确认次数 256 变成 0 | IP 与 RTL 位宽保持一致，或在 RTL 中饱和处理 |
| C5 | 增益为正时假设"DAC 增大 → 功率增大" | 工作点斜率相反时变成正反馈 | 反馈极性由增益符号设定，上板前确认局部斜率方向 |

## D. 调试与观测

| # | 触发条件 | 现象 | 排查与解决 |
|---|---|---|---|
| D1 | 同一信号同时接 VIO 和 ILA | ILA 中显示名被加 `_1` 后缀，脚本按名称找不到 | 按探针编号对应，脚本中允许 `_1` 后缀匹配 |
| D2 | 下载的 BIT 与 LTX 不是同一次构建 | VIO 缺少探针、参数恢复失败 | 恢复脚本检查期望探针，缺失时提示重新生成并成对下载 |
| D3 | 有符号 VIO 探针在无符号进制下保存 | 恢复后变成 65535 一类的补码值 | 统一保存为十进制有符号值，恢复时兼容旧补码，见 `vio_param_save_restore/` |
| D4 | 用状态码判断事件先后 | 寄存器输出比事件晚 1 个控制周期 | 精确判断时同时看底层信号 |
| D5 | xsim 中 `$fatal` 退出 | 启动脚本可能仍返回成功 | 只认 `PASS: <平台名>` 哨兵，见 `regression_with_sentinel/` |
| D6 | 比较示波器不同通道几百 ns 内的先后 | 探头、线缆延迟差与被测时间差同一量级 | 不据此下因果结论，必要时用同一通道或 ILA 时间戳确认 |

## E. 文档与提交

| # | 触发条件 | 现象 | 排查与解决 |
|---|---|---|---|
| E1 | 用 Unicode 下标/上标字符（Si₃N₄、10⁶） | 在 WPS 中字形缺失，字符之间出现空隙 | 改为普通数字 + 字体上下标格式 |
| E2 | 用 LibreOffice 等非 Word 工具把含公式的 docx 转为 PDF | OMML 公式显示为空白 | 用 Word/WPS 导出 PDF 并人工翻阅 |
| E3 | 脚本批量替换 docx 中的图号、数值 | 同一段文字被拆成多个 run，替换遗漏 | 按段落拼接文本定位，再映射回各 run 修改 |
| E4 | 同一指标在摘要、正文、表格中分别修改 | 出现两种口径并存、自相矛盾 | 修改后全文搜索该指标的所有出现位置 |
| E5 | 概括性描述多个时间点（如"120 ns 内重新扫描和 kick"） | 把相隔数毫秒的事件写成同时发生 | 回到 ILA / 示波器原始记录逐点核对 |
